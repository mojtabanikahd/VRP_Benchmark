# استودیوی مسیر VRP

[English](README.md) · **فارسی**

رابط تعاملی حل‌کننده‌های [vrpbench](../README.fa.md). مرورگر سناریو را ویرایش می‌کند. یک سرویس کوچک FastAPI همان سناریو را به یک نمونهٔ `vrpbench` تبدیل می‌کند، حل‌کنندهٔ انتخاب‌شده را اجرا می‌کند، و جوابی برمی‌گرداند که خود چارچوب آن را بررسی کرده است.

دو صفحه در یک پنجره هستند:

| صفحه | چه چیزی حل می‌شود | نقاط کجا قرار می‌گیرند |
| --- | --- | --- |
| **Studio** | CVRP، VRPTW، یا MDVRP | یک صفحهٔ تخت اقلیدسی. فایل بنچمارک هم قابل بارگذاری است. |
| **سوخت‌رسانی** | VRPTW تک‌انباره برای سوخت‌رسانی ماشین‌ها | یک OpenStreetMap. مسافت و زمان سفر از شبکهٔ خیابان می‌آید و هر مسیر حل‌شده روی همان خیابان‌ها کشیده می‌شود. |

استودیو انگلیسی و چپ‌به‌راست می‌ماند. سوخت‌رسانی فارسی، راست‌به‌چپ، و با قلم وزیرمتن است. نقشهٔ آن چپ‌به‌راست می‌ماند تا جابه‌جایی و بزرگ‌نمایی Leaflet درست کار کند. هر صفحه هنگام تعویض، سناریوی خودش را نگه می‌دارد.

## پیش‌نیازها

اول خود چارچوب را از ریشهٔ مخزن نصب کنید. راهنمای سیستم‌عامل شما در [README اصلی](../README.fa.md#نصب) است ([English](../README.md#installation)). بعد قطعه‌های مخصوص این برنامه را اضافه کنید:

| پیش‌نیاز | نسخه | نقش |
| --- | --- | --- |
| Python | ۳.۱۱ یا جدیدتر | از قبل برای vrpbench لازم است. |
| extra با نام `web` | FastAPI، Uvicorn، python-multipart | API در `web/api`. |
| Node.js | ۲۰ یا جدیدتر | رابط Vite در `web/app`. |
| npm | همراه Node.js | یک بار وابستگی رابط را نصب می‌کند. |
| شبکه | هنگام استفاده از سوخت‌رسانی | کاشی نقشه، جست‌وجوی نشانی، و مسافت رانندگی. |

استودیو، بعد از نصب حل‌کننده‌ها، بدون شبکه هم حل می‌کند. سوخت‌رسانی کاشی را از OpenStreetMap می‌گیرد، نشانی تایپ‌شده را از سرویس عمومی Nominatim می‌پرسد، و به‌طور پیش‌فرض مسافت رانندگی و هندسهٔ خیابان را از سرور نمایشی عمومی OSRM می‌گیرد.

## نصب

فرمان‌های پایتون را از **ریشهٔ مخزن** اجرا کنید؛ همان پوشه‌ای که `pyproject.toml` در آن است. فرمان npm را از `web/app` اجرا کنید. اگر `vrpbench` از قبل در `.venv` نصب شده، همان محیط را نگه دارید و فقط extra با نام `web` را اضافه کنید.

پیش از نصب رابط، Node.js را بررسی کنید:

```bash
node --version
```

عدد باید ۲۰ یا بزرگ‌تر باشد. نصب‌کننده‌های جاری: [nodejs.org](https://nodejs.org/)، در ویندوز `winget install OpenJS.NodeJS.LTS`، در لینوکس بستهٔ NodeSource یا توزیع، و در مک `brew install node`.

### ویندوز

PowerShell، از ریشهٔ مخزن. از همان محیط مجازی نصب چارچوب استفاده کنید:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[web]"
cd web\app
npm install
```

گیومه دور `".[web]"` لازم است. PowerShell کروشه را wildcard می‌گیرد.

اگر محیط مجازی هنوز نیست، اول آن را با [گام‌های ویندوز](../README.fa.md#ویندوز) در README اصلی بسازید و بعد دو فرمان بالا را اجرا کنید.

### لینوکس

```bash
source .venv/bin/activate
python -m pip install -e ".[web]"
cd web/app
npm install
```

اگر محیط مجازی نیست، اول آن را بسازید: [گام‌های لینوکس](../README.fa.md#لینوکس).

### مک

```bash
source .venv/bin/activate
python -m pip install -e ".[web]"
cd web/app
npm install
```

اگر محیط مجازی نیست، اول آن را بسازید: [گام‌های مک](../README.fa.md#مک). از Node.js نسخهٔ ۲۰ به بالا، از Homebrew یا nodejs.org، استفاده کنید؛ نه از نسخهٔ قدیمی‌تری که شاید از قبل روی `PATH` باشد.

## اجرا

API و رابط دو فرایند هستند. API را پیش از حل روشن کنید. صفحه بدون آن هم باز می‌شود، ولی تا وقتی API جواب ندهد فهرست حل‌کننده‌ها خالی می‌ماند.

Vite مسیر `/api` را به `http://127.0.0.1:8000` پروکسی می‌کند. API را روی همین نشانی بگذارید، مگر اینکه `web/app/vite.config.ts` را هم هماهنگ تغییر دهید.

### ویندوز

```powershell
# پایانهٔ ۱، ریشهٔ مخزن
.\.venv\Scripts\python.exe -m uvicorn web.api.main:app --host 127.0.0.1 --port 8000
```

```powershell
# پایانهٔ ۲
cd web\app
npm run dev -- --host 127.0.0.1 --port 5173
```

### لینوکس و مک

```bash
# پایانهٔ ۱، ریشهٔ مخزن، با محیط مجازی فعال
python -m uvicorn web.api.main:app --host 127.0.0.1 --port 8000
```

```bash
# پایانهٔ ۲
cd web/app
npm run dev -- --host 127.0.0.1 --port 5173
```

[http://127.0.0.1:5173](http://127.0.0.1:5173) را باز کنید. نوار بالا بین **Studio** و **سوخت‌رسانی** جابه‌جا می‌شود.

## استودیو

استودیو سناریو را روی یک صفحهٔ تخت ویرایش می‌کند. مختصات انتزاعی است. مسافت اقلیدسی است و با بارگذار بنچمارک یکی است: برای CVRP و MDVRP گردشده به نزدیک‌ترین عدد صحیح، و برای VRPTW اقلیدسی خام.

1. سناریو را نام‌گذاری کنید.
2. **CVRP**، **VRPTW**، یا **MDVRP** را انتخاب کنید.
3. حل‌کننده را انتخاب کنید. CVRP و VRPTW فهرست PyVRP، OR-Tools، VROOM، و VRPSolverEasy را نشان می‌دهند. MDVRP فهرست PyVRP، OR-Tools، و VROOM را نشان می‌دهد. حل با VRPSolverEasy به [کتابخانهٔ BaPCod](../BAPCOD_SETUP.md) نیاز دارد.
4. ظرفیت وسیله، بودجهٔ زمانی حل (۱ تا ۶۰ ثانیه)، و بذر تصادفی را تنظیم کنید. OR-Tools بذر را نادیده می‌گیرد.
5. برای افزودن مشتری روی صفحه کلیک کنید. برای جابه‌جایی، نقطه را بکشید. روی نقطه کلیک کنید و آن را در **Inspector** ویرایش کنید، یا همهٔ نقطه‌ها را زیر **Nodes** ببینید.
6. با **Delete** یا **Backspace** مشتری انتخاب‌شده را بردارید. آخرین انبار برداشته نمی‌شود. MDVRP حداقل دو انبار نگه می‌دارد؛ انبار بیشتر با **Add depot** اضافه می‌شود.
7. برای VRPTW، تقاضا و پنجرهٔ زمانی هر مشتری (آمادگی، سررسید، و مدت خدمت) را در بازرس تنظیم کنید.
8. **Solve** را بزنید. نوار پایین مسافت تأییدشده، شدنی بودن جواب، و مسیرها را نشان می‌دهد. روی یک مسیر کلیک کنید تا روی صفحه برجسته شود.

**Load instance** یک فایل `.vrp` یا `.txt` برای گونهٔ انتخاب‌شده می‌خواند و نقطه‌های صفحه را جایگزین می‌کند.

تا وقتی سناریو ناقص است، حل غیرفعال می‌ماند: CVRP و VRPTW دقیقاً یک انبار و حداقل یک مشتری می‌خواهند، MDVRP حداقل دو انبار می‌خواهد، و تقاضای هیچ مشتری‌ای نباید از ظرفیت بیشتر باشد. پنجرهٔ VRPTW باید در لحظه‌ای باز شود که دیرتر از لحظهٔ بسته‌شدن آن نباشد.

## سوخت‌رسانی

سوخت‌رسانی یک انبار و یک ظرفیت تانکر است. هر ماشین می‌تواند با تانکری سرویس بگیرد که از همان انبار شروع می‌کند و به همان انبار برمی‌گردد. مسیرها را حل‌کننده انتخاب می‌کند. صفحه فارسی و راست‌به‌چپ است. نام‌های زیر همان برچسب‌های روی صفحه هستند.

| روی صفحه | معنی |
| --- | --- |
| ماشین | تجهیزی که سوخت می‌خواهد. این یک مشتری VRPTW است. |
| انواع ماشین | یک نام، یک تصویر نشانگر، سوخت پیش‌فرض به لیتر (**سوخت پیش‌فرض**)، و مدت سوخت‌گیری پیش‌فرض به دقیقه (**مدت سوخت‌گیری پیش‌فرض**). ماشین تازه آن دو پیش‌فرض را کپی می‌کند. عوض کردن نوع یک ماشین، پیش‌فرض‌های آن نوع را دوباره کپی می‌کند. ویرایش بعدی نوع، ماشین‌هایی را که از قبل روی نقشه هستند عوض نمی‌کند، و هر ماشین همچنان می‌تواند سوخت و مدت خودش را داشته باشد. |
| تانکر | یک مدل: نام، ظرفیت مخزن به لیتر صحیح (**ظرفیت مخزن**)، و تصویر نشانگر انبار. همهٔ تانکرهای ناوگان از همین ظرفیت استفاده می‌کنند. |
| انبار | تنها پایگاه. نشانگرش تصویر تانکر است. تانکرها سنجاق جدا نیستند. |
| سوخت موردنیاز | لیتری که آن ماشین باید بگیرد. |
| شروع پنجره / پایان پنجره | بازهٔ ساعتی که کل سوخت‌گیری باید در آن انجام شود. خدمت در لحظهٔ باز شدن یا بعد از آن شروع می‌شود و در لحظهٔ بسته شدن یا پیش از آن تمام می‌شود. |
| مدت سوخت‌گیری | دقیقه‌ای که تانکر کنار آن ماشین می‌ماند. باید داخل پنجرهٔ همان ماشین جا شود. |
| مسافت رانندگی | کیلومتر خیابان. این همان هدف است. |
| زمان رانندگی | دقیقهٔ خیابان، از OSRM. پنجرهٔ سوخت‌گیری با همین زمان سنجیده می‌شود، نه با کیلومتر. در نوار پایین رقم جداگانه‌ای برای آن نیست. |

### ساخت سناریو

1. زیر **انواع ماشین** هر گونه را نام بگذارید، لیتر و دقیقهٔ پیش‌فرض را تنظیم کنید، و برای عوض کردن تصویر روی بندانگشتی کلیک کنید. تصویر باید ۲۰۰ کیلوبایت یا کوچک‌تر باشد. نوع تازه از ۱۰۰ لیتر و ۱۵ دقیقه شروع می‌شود.
2. زیر **تانکر** نام، ظرفیت مخزن به لیتر، و تصویر را تنظیم کنید. همین یک مدل، ناوگان است.
3. **PyVRP** یا **OR-Tools** را انتخاب کنید، سپس **بودجهٔ زمانی** (۱ تا ۶۰ ثانیه) و **بذر** را تنظیم کنید.
4. روی نقشه، **تعیین انبار**، **گذاشتن ماشین**، و **انتخاب** بالا-راست هستند. بزرگ‌نمایی و کوچک‌نمایی بالا-چپ هستند. جعبهٔ نشانی بالای صفحه است، سمت راست کنترل بزرگ‌نمایی و دور از آن سه ابزار.
5. نشانی را بنویسید و **جستجو** یا Enter را بزنید. API تا پنج تطبیق از Nominatim می‌گیرد (`GET /api/fueling/geocode`) و نقشه همان محدوده را قاب می‌کند. اگر محدوده فقط یک نقطه باشد، حدود سطح خیابان می‌ایستد. یک نقطهٔ مسی تطبیق را نشان می‌دهد. این نقطه انبار یا ماشین نیست، و کلیک روی آن همچنان ابزار فعال را می‌گذارد. سطر دیگری زیر جعبه را انتخاب کنید تا آن تطبیق قاب شود. جست‌وجو یک بار در هر ارسال اجرا می‌شود، نه با هر کلید. پرسش خالی رد می‌شود.
6. **تعیین انبار** را انتخاب کنید و یک بار کلیک کنید تا انبار گذاشته شود. نشانگر را بکشید تا جابه‌جا شود. پنل **جزئیات** نام انبار و شیفت را تنظیم می‌کند (**شروع شیفت** / **پایان شیفت**): کی تانکرها می‌توانند خارج شوند و کی باید برگردند.
7. **گذاشتن ماشین** را انتخاب کنید و برای هر ماشین روی نقشه کلیک کنید. ماشین تازه با سوخت و مدت پیش‌فرض نوع خودش، و پنجرهٔ ۰۸:۰۰ تا ۱۶:۰۰، شروع می‌شود. **جزئیات** نام، نوع ماشین، سوخت به لیتر، پنجرهٔ سوخت‌گیری، و مدت سوخت‌گیری را تنظیم می‌کند. **انتخاب** و بعد کلیک روی نشانگر، آن نقطه را در **جزئیات** باز می‌کند، بدون پنجرهٔ بازشو. نشانگر انتخاب‌شده کمی بزرگ می‌شود و حلقهٔ مسی می‌گیرد. اشاره‌گر را روی نشانگر نگه دارید تا نامش کنار آیکن بیاید.
8. **حذف** در **جزئیات** و روی هر سطر **فهرست**، انبار یا ماشین انتخاب‌شده را پاک می‌کند. **Delete** یا **Backspace** هم همین کار را می‌کند، مگر وقتی در یک فیلد تایپ می‌کنید. برداشتن هر کدام از این نقطه‌ها مسیرهای قبلی را پاک می‌کند.
9. در **فهرست**، روی نام انبار یا ماشین کلیک کنید تا انتخاب شود، جزئیاتش باز شود، و نقشه به سمت آن برود. اگر نقشه از سطح خیابان دورتر باشد، نزدیک می‌شود. **حذف** روی همان سطر نقطه را پاک می‌کند و نقشه را جابه‌جا نمی‌کند.

**حل** تا وقتی انبار، حداقل یک ماشین، یک تانکر، و یک حل‌کننده نباشد غیرفعال می‌ماند. سوخت هر ماشین هم باید عدد صحیح لیتر و حداکثر به‌اندازهٔ مخزن باشد، و مدت سوخت‌گیری هر ماشین باید داخل پنجرهٔ خودش جا شود. یادداشت زیر کنترل‌ها می‌گوید چه چیزی کم است.

### ذخیره، بارگذاری، واگرد، و بازنشانی

**ذخیره** یک فایل `.fueling.json` بارگیری می‌کند. هر چه برای بازسازی سناریو لازم است در آن است: نام، انواع ماشین (شامل سوخت پیش‌فرض، مدت سوخت‌گیری، و تصویر هر کدام)، تانکر، انبار و هر ماشین با موقعیت نقشه و فیلدهای سوخت‌گیری، به‌علاوهٔ حل‌کننده، بودجهٔ زمانی، و بذر. **بارگذاری** سناریوی روی صفحه را جایگزین می‌کند و نقشه را روی همان موقعیت‌ها میزان می‌کند. فایلی که چند نوع تانکر داشته، همان نوعی را نگه می‌دارد که انتخاب شده بود. فایلی که پیش از وجود پیش‌فرض انواع ماشین ذخیره شده، آن پیش‌فرض‌ها را ۱۰۰ لیتر و ۱۵ دقیقه بار می‌کند. فایل قدیمی‌تری که حل‌کننده را نداشته، حل‌کننده و بودجه و بذر همان صفحه را نگه می‌دارد.

**واگرد** و **ازنو** ویرایش‌های سناریو را قدم‌به‌قدم برمی‌گردانند: نام‌ها، انواع، تانکر، جاگذاری‌ها، پنجره‌ها، بارگذاری فایل، یک حل، و بازنشانی. حدود ۱۰۰ قدم آخر نگه داشته می‌شود. انتخاب نشانگر، عوض کردن ابزار نقشه، و بزرگ‌نمایی قدم نیستند. همان کارها، وقتی مکان‌نما داخل فیلد متن نیست، با `Ctrl+Z` و `Ctrl+Y` (یا `Ctrl+Shift+Z`) هم انجام می‌شود. **بازنشانی** صفحه را به سناریوی خالی اولیه برمی‌گرداند (یک نوع ماشین، یک تانکر، بدون انبار، بدون ماشین، بدون جواب) و خودش قدمی است که می‌شود واگرد کرد.

### حل چه چیزی نشان می‌دهد

API مسافت و زمان رانندگی بین انبار و هر ماشین را از OSRM می‌گیرد، VRPTW را حل می‌کند، بعد هندسهٔ کامل خیابان هر مسیر را از OSRM می‌گیرد. نقشه همان هندسه را می‌کشد. بین توقف‌ها خط راست نمی‌کشد. یک خط‌چین متحرک هر مسیر را به ترتیب رانندگی دنبال می‌کند، از انبار تا توقف‌ها و برگشت. شمارهٔ توقف روی ماشین‌ها ترتیب بازدید را نشان می‌دهد.

ساعت، بازهٔ سوخت‌گیری است، نه لحظه‌ای که تانکر می‌رسید اگر درست هنگام باز شدن شیفت انبار حرکت کرده بود. حرکت طوری عقب می‌افتد که به ماشین اول هنگام باز شدن پنجره‌اش برسد، به شرطی که پنجره‌های بعدی و برگشت به انبار هنوز برقرار بمانند. اگر به توقف بعدی هنوز زود برسد، تانکر آنجا منتظر می‌ماند و برچسب شروع و پایان سوخت‌گیری را نشان می‌دهد. خدمت باید تا بسته شدن پنجره تمام شود. انتخاب یک مسیر در نوار پایین، فقط بازه‌های همان مسیر را روی نقشه می‌گذارد.

نوار پایین مجموع مسافت رانندگی را به کیلومتر می‌گوید، اینکه برنامه **شدنی** است یا **نشدنی**، و چند تانکر به کار رفته است. مدت اجرای حل‌کننده را گزارش نمی‌کند. هر کارت مسافت آن سفر، خروج از انبار، بازهٔ سوخت‌گیری هر ماشین، کیلومتر هر پرش، و برگشت به انبار را نشان می‌دهد، بعد نام خیابان‌های همان رانندگی را. قطعه‌هایی که مسیریاب برایشان نام نداده **خیابان‌های بدون نام** برچسب می‌گیرند.

روی کارت یک تانکر کلیک کنید تا آن مسیر مسی کشیده شود، مسیرهای دیگر کم‌رنگ شوند، و نقشه روی آن میزان شود. کلیک دوباره برجسته‌سازی را برمی‌دارد. روی یک توقف کارت — انبار یا یک ماشین — کلیک کنید تا نقشه به آن نشانگر برود و آن را انتخاب کند. مسیر تانکر برجسته می‌ماند.

اگر هیچ مسیری حتی با زودترین خروج مجاز از انبار نتواند پنجره‌ها را رعایت کند، کار با خطا می‌ایستد و چیزی کشیده نمی‌شود. تنها برنامهٔ شدنی کشیده می‌شود.

جابه‌جا کردن انبار یا یک ماشین مسیرهای قبلی را پاک می‌کند، چون دیگر با موقعیت‌ها نمی‌خوانند.

یک سناریوی سوخت‌رسانی حداکثر ۹۹ ماشین دارد. سرور نمایشی عمومی OSRM جدول را حدود ۱۰۰ مختصات محدود می‌کند (انبار به‌علاوهٔ ماشین‌ها) و برای استفادهٔ سنگین ساخته نشده است. برای یک نمونهٔ دیگر OSRM، پیش از شروع Uvicorn متغیر `OSRM_BASE_URL` را در محیط همان فرایند API بگذارید. پیش‌فرض `https://router.project-osrm.org` است.

جست‌وجوی نشانی سرویس عمومی Nominatim را (`https://nominatim.openstreetmap.org/search`) یک بار در هر جست‌وجو، با ترجیح زبان فارسی، صدا می‌زند و نام، نقطه، و کادر هر تطبیق را برمی‌گرداند. برای جست‌وجوی انبوه ساخته نشده است.

## اگر چیزی درست پیش نرفت

- **فهرست حل‌کننده‌ها در دسترس نیست.** API روشن نیست، یا روی درگاه ۸۰۰۰ نیست. Uvicorn را شروع کنید و صفحه را تازه کنید.
- **حل غیرفعال می‌ماند.** یادداشت زیر کنترل‌ها را بخوانید. انبار، مشتری، یا ماشین جاافتاده، سوختی بزرگ‌تر از مخزن، یا مدت سوخت‌گیری‌ای که در پنجره‌اش جا نمی‌شود را نام می‌برد.
- **هیچ برنامه‌ای پنجرهٔ زمانی سوخت‌گیری را رعایت نمی‌کند.** رانندگی نمی‌تواند داخل پنجره به یک ماشین برسد، یا نمی‌تواند پیش از بسته شدن آن پنجره سوخت‌گیری را تمام کند و هنوز در شیفت انبار برگردد. پنجره را بازتر کنید، شیفت انبار را بلندتر کنید، یا نقطه را جابه‌جا کنید. نقشه آن برنامه را نمی‌کشد.
- **مسیر خیابان پیدا نشد.** OSRM هندسهٔ خیابان یک مسیر را برنگرداند. نقشه آن مسیر را نکشیده رها می‌کند و به‌جایش خط راست نمی‌گذارد. اتصال شبکه را بررسی کنید، یا `OSRM_BASE_URL` را به یک سرور OSRM در دسترس ببرید.
- **نتیجه‌ای پیدا نشد.** Nominatim برای آن متن جایی برنگرداند. نشانی مشخص‌تری امتحان کنید.
- **جستجوی آدرس برقرار نشد.** API به Nominatim نرسید. اتصال شبکه را بررسی کنید.
- **نقشهٔ سوخت‌رسانی خالی است.** مرورگر کاشی OpenStreetMap را بار نکرد. صفحه به `tile.openstreetmap.org` نیاز دارد.
